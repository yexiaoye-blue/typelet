# 内容与练习模式实现规划

2026-10-15，基于已确认的产品决定和当前仓库状态整理。本文是下一步实现计划，不改变当前已实现行为；实现完成后再把实际结果补到验证记录。

## 目标和边界

下一步完成三件事：把练习内容和打字处理的所有权移到 Rust；加入句子模式的内置文章和本地导入；加入只练英文单词的词库、音标、释义和朗读。

窗口继续以 380 × 450 为主要尺寸，允许拉到 460 × 650。句子模式的练习单位是一句，单词模式的练习单位是一个单词。本轮不保存打到一半的输入，不做章节格子、错词本、听写隐藏或学习算法。

## 1. 内容所有权和快照契约

当前 packages/core/typing.ts 同时保留了 TypeScript 打字算法和中英文 passages，src/App.svelte 通过 passageIndex 选择目标，桌面端再把目标字符串传给 typing_snapshot。下一步按以下顺序收拢边界：

1. 在 Rust 中建立统一的内容模型，至少区分句子文章、句子单元、词书和单词条目。Rust 负责内置内容、导入内容、词条读取、文章切句、章节或词序切片，以及当前练习项的选择。
2. 把 typing_snapshot 改成以 Rust 当前练习项为目标计算快照。前端只提交用户输入值和必要的计时/操作信息；返回值包含当前练习项文本、练习累计状态、统计值和完成状态，使界面不需要自行维护 passageIndex 或重新推导目标。
3. 对“完成当前项”和“回车换下一项”建立明确的 Rust command 边界。完成后不自动跳词；用户按回车时由 Rust 按文章句序或词书顺序切换，并返回新的空练习快照。
4. 选中的文章和词书名称可以写入本机设置，启动时恢复选择；正在输入的 Practice、计时和光标位置不写入磁盘。dirs 已存在，后续实现沿用应用数据目录，不把内容写到项目目录。
5. Rust 桌面运行路径是唯一结果来源。Svelte 只负责输入框、焦点、计时展示、按钮和快照渲染，把用户操作交给 Tauri command。

### 网页预览回退如何与 Rust 对齐

网页预览仍需要在没有 Tauri runtime 时运行，因此 packages/core/typing.ts 可以保留 freshPractice、characters、updatePractice 和 statistics 作为回退实现，但不再把 passages 当作桌面内容源。预览回退使用同一组小型预览内容和同一份快照字段，内容顺序、Unicode NFC 归一化、退格累计错误、完成判断、正确率和 CPM 规则必须通过 Rust/TypeScript 共享测试向量核对。

实现时先固定这些跨端样例：空输入、追加正确字符、替换错误字符、退格后重新输入、中文和非 BMP 字符、输入超过目标、完成后回车。网页模式只模拟 command 的输入输出形状；它不能决定桌面端文章、词书或当前项。

## 2. 句子模式

### 内置内容

应用内置几篇短的公有领域节选，每篇有稳定的名称和来源说明。每篇文章在 Rust 侧保存原始正文，加载后清理 BOM、统一换行并去掉首尾空白；段落之间的换行不作为用户必须输入的额外字符。

文章切句也在 Rust 完成：保留句末标点在当前句中，过滤空句；中英文句末标点至少覆盖 . ! ? 。！？” 以及成对引号结束的常见情况。没有可识别句末标点的短段落作为一个句子单元。实现时用固定测试样例确认缩写、小数、连续标点和引号不会把一句错误切成多句。

句子列表按文章原顺序切片。主窗口一次只展示一句，完成后仍停留在完成态，提示用户按回车进入下一句；回车换句时清空当前输入和统计，但不自动朗读、不跳到下一篇。设置中记住当前文章，暂不记住句内进度。

### 句子文章导入

Typelet 选择 **UTF-8 纯文本 .txt** 作为文章导入格式：

- 一个文件表示一篇文章或一组连续正文，文件名作为默认标题。
- 文件内容就是正文，不加 JSON/XML 包装，不要求用户填写字段。
- 空行用于段落分隔；正文中的普通换行在解析时归并为空格，避免把排版换行变成必须输入的字符。
- 导入后由 Rust 执行同一套清理和切句规则；用户不能通过前端直接注入已经切好的目标字符串。
- 文件以 UTF-8 读取；无法解码、正文为空或清理后没有句子时，返回带行号或原因的可见错误，不生成空文章。

示例 meditations.txt：

~~~text
You have power over your mind—not outside events. Realize this, and you will find strength.

The happiness of your life depends upon the quality of your thoughts.
~~~

首版不直接解析 EPUB、PDF、DOCX 或 HTML。TypeLit 的产品路径是整本公有领域书籍，并把一次练习做成句子、段落或章节；Amphetype 也支持导入整本小说后生成短课，这证明“导入整篇纯文本再切小段”是打字工具的常见做法，但不要求 Typelet 承担电子书、版式和复杂编码解析。Typelet 的窗口小、练习单位固定为一句，先用纯文本可以保持 Rust 解析器和错误提示可控；以后若确实需要电子书，再单独设计格式转换，不把它混入本轮契约。

## 3. 单词模式

### 内置词书和生成方式

词库源使用 https://github.com/kajweb/dict。不把约 72 MB 的原库直接打进应用；仓库外或开发工具中提供一次性转换脚本，抽取新东方四级 CET4_3 的 2607 个词，生成应用实际读取的扁平记录：

~~~json
{
  "name": "abandon",
  "trans": ["放弃；遗弃"],
  "usphone": "əˈbændən",
  "ukphone": "əˈbændən"
}
~~~

生成结果只保留 name、trans、usphone、ukphone。转换时去重、过滤空词条，保留英文词形和原始释义/音标；脚本输出词条数应为 2607，缺少 name 的记录直接报告并停止打包。

该仓库没有许可证，且数据来自有道/新东方。文档和应用关于页必须明确：词库只用于本机练习，不原样再发布词书。打包时只放转换后的练习数据，不把源仓库或完整原始数据作为应用资源发布。

### 交互

- 单词模式仅练英文，一次显示一个单词。
- 单词旁显示美式和英式音标；释义显示 trans 内容，没有释义时显示可理解的缺失状态，不阻止打字。
- 单词完全拼对后保持完成态，默认朗读一次；不自动跳到下一个词。
- 用户按回车才进入下一个词，并按当前词书顺序切片；回车换词后清空输入、统计和发音状态。
- 首选有道发音地址 https://dict.youdao.com/dictvoice?audio=单词&type=2。网络失败、请求失败或离线时调用系统语音；失败回退不能阻塞完成或换词。
- 只记住选中的词书，不记住正在输入的单词进度。

### 单词词表导入

Typelet 选择 **带表头的 UTF-8 制表符分隔文本（TSV，扩展名建议 .tsv，也接受 .txt）**。这是一个轻量的平面格式，方便从表格、Anki 文本导出和常见词典单词本整理出来，也不会因为释义中的逗号而产生 CSV 歧义。

表头和字段规则：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| name | 是 | 要练习的英文单词，去除首尾空白后不能为空；首版不接受包含空格的短语 |
| trans | 否 | 一个或多个释义；多个释义用“；”分隔，导入后保存为字符串数组 |
| usphone | 否 | 美式音标 |
| ukphone | 否 | 英式音标 |

字段顺序按表头决定；首版只接受这四个字段，重复字段、缺少 name 或无法解析的表头直接报错。缺少可选字段时保持空值，之后仍可用有道朗读或系统语音练习。每行一个词条，UTF-8 BOM 可忽略；完全相同的 name 只保留首次出现的记录，并在导入结果中报告重复数量。

示例 cet4.tsv：

~~~text
name	trans	usphone	ukphone
abandon	放弃；遗弃	əˈbændən	əˈbændən
ability	能力；才能	əˈbɪləti	əˈbɪləti
access	接近；进入；通道	ˈækses	ˈækses
~~~

只有单词的常见列表也按同一契约导入，写成表头为 name、之后每行一个英文词即可：

~~~text
name
abandon
ability
access
~~~

不选择 Qwerty Learner 使用的项目内 JSON 词库作为用户导入格式。它适合作为开发者提交内置词库的结构，但要求用户编辑数组和字段，不如 TSV 能直接从电子表格或词典单词本导出。也不选择 Anki .apkg：它包含牌组、卡片模板、媒体和复习状态，超出 Typelet 的一次练一个词边界；只吸收 Anki 文本导出的制表符字段习惯。对文章同样不选择 EPUB/PDF/DOCX，因为解析版式和章节资源会放大依赖、错误处理和跨平台验证范围。

## 4. Tauri command 和数据流落地顺序

1. 先在 Rust core 固定内容模型、切句、词条读取、练习状态和快照序列化，再补桌面 command。每个 command 的输入输出都用可序列化结构体描述，错误带稳定的用户可读原因。
2. 加入内置文章和转换后的 CET4 数据，先让桌面端可以列出文章/词书、选择当前内容、读取当前练习项和切换下一项。
3. 增加本地文件选择入口。当前仓库还没有文件对话框插件；实现时引入 Tauri 2 对应的文件对话框能力，只把选中的路径交给 Rust 读取和解析，不让 Svelte 读取文件内容再自行切分。
4. 把 App.svelte 的 passages、passageIndex 和桌面端目标字符串传参替换为 Rust 返回的内容快照。主页面只根据快照画字符、进度、速度、正确率和音标/释义。
5. 加入文章和词表的导入预览：显示文件名、识别条数、首个条目和错误行；确认后保存到应用数据目录。导入失败不覆盖已有内容，重复词条按首次出现保留并报告数量。
6. 加入发音服务和系统语音回退，完成态朗读只执行一次；网络请求失败要有短错误状态，但不能改变 Rust 的完成统计。
7. 最后接入网页预览回退，使用相同快照样例和小型预览数据，不模拟本地文件、网络发音或桌面路径权限。

## 5. 验收条件

- 桌面端不再从 packages/core/typing.ts 读取文章或词条，当前目标和切换顺序均可由 Rust 快照解释。
- Rust 单测覆盖 Unicode NFC、退格累计错误、文章切句、空行和引号、TSV 表头/可选字段/重复词条/错误行，以及 2607 条 CET4 转换结果。
- 同一组输入向量在 Rust 和网页回退中产生相同的 practice、统计和完成状态。
- 内置文章能按句练习；完成后不自动切句，回车才切换；窗口尺寸 380 × 450 下句子和单词的目标区都不产生不可操作的溢出。
- 单词完成后只默认朗读一次，断网时系统语音回退，回车才换词；不出现章节格子、错词本或听写隐藏入口。
- 文章 .txt 和词表 .tsv/.txt 的错误都能在界面显示具体原因；成功导入后重启应用仍能找到已保存的文章、词书和当前选择。
- 文档明确词库来源、无许可证事实和“仅作本机练习、不原样再发布词书”的限制。

## 社区依据

本次格式决定核对了以下资料（核对日期：2026-10-15）：

- Monkeytype 自定义文本讨论：https://github.com/monkeytypegame/monkeytype/discussions/8316。自定义文本入口支持导入 .txt，说明打字练习软件常把用户文章先按纯文本处理。
- Amphetype README：https://github.com/DNS/amphetype/blob/master/README.md。支持导入整本小说，并自动生成短小练习，支持“整篇文本导入后再切片”的文章模型。
- TypeLit 首页：https://www.typelit.io/。产品以整本文学作品为练习内容，并提供导入自有内容的路径；这支持把文章内容和练习顺序作为内容库能力处理。
- Qwerty Learner 词典构建说明：https://github.com/RealKai42/qwerty-learner/blob/master/docs/toBuildDict.md。内置词库采用 JSON 数组，每条包含 name 和 trans，适合作为 Rust 内置数据转换的参考。
- Anki 文本导入手册：https://docs.ankiweb.net/importing/text-files.html 与文本导出手册：https://docs.ankiweb.net/exporting.html。纯文本可用制表符分隔字段，支持表头和字段映射；这是选择 TSV 作为词表交换格式的主要依据。
- 欧路/常见词表资料：桌面词典和单词本常见逐行单词、Excel 或“单词 + Tab + 释义”的交换路径；这些资料用于确认用户侧的轻量整理习惯，和 name 必填、其他字段可选的 Typelet TSV 兼容。
