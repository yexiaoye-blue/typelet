# 后续规划

2026-10-14，已确认的产品方向。以下三项尚未实现，接入方案和数据格式也尚未确定。

Typelet 继续保持小巧的跨平台悬浮打字工具定位：让等待 Agent 完成任务的时间可以用来练习打字。

## 1. Agent 运行时自动唤起

在设置中添加配置，让用户选择要响应哪些 Agent，并开启或关闭自动唤起。选中的 Agent 开始运行时，启动或显示 Typelet；应用已经打开时复用现有窗口。

第一版已经完成 Codex：设置页提供 Codex 开关，应用会自动维护 .codex/config.toml 中带有 Typelet 标记的 UserPromptSubmit 配置块。提交 Codex 任务时会运行 typelet，单实例机制负责显示、还原并聚焦已有窗口。关闭开关时只移除 Typelet 自己的配置块，不需要用户手动编辑文件。Codex 首次可能要求确认新增 hook。

后续继续调研其他 Agent 实际提供的能力，再决定适配方式。公开事件、hooks、官方扩展接口或其他可用机制都属于候选，不假设各家存在统一的 hooks，也不预先承诺支持列表。

待确定：

- 第一批支持的 Agent，以及各自能够可靠识别的运行事件。
- 各平台如何接收事件、启动应用或显示已有窗口。
- 唤起时是否获得输入焦点，以及重复事件的处理方式。

## 2. 句子与单词模式

在设置中增加“句子 / 单词”两种练习模式。当前连续文本练习归入句子模式；单词模式一次展示一个单词，支持输入练习、发音播放和翻译显示，保留当前的字符反馈与基本统计。

单词模式的交互参考 [Qwerty Learner](https://qwerty.kaiyi.cool/)，其[项目说明](https://github.com/RealKai42/qwerty-learner#readme)介绍了单词练习与发音功能。这里记录产品参考，不预先决定复用其代码、词库或音频。

待确定：

- 发音与翻译的数据来源，哪些能力可以离线使用。
- 发音的自动播放与手动播放规则，以及翻译的显示时机。
- 单词完成、出错和切换到下一词的交互规则。

## 3. 自定义内容导入

允许用户导入自己的句子或词库，并在对应练习模式中使用。导入后的内容也应能继续在小窗中练习。

待确定：

- 支持的文件格式，以及句子与词库各自的数据字段。
- 单词的翻译、发音等附加信息是否允许随文件导入。
- 导入入口、预览与校验、重复内容处理，以及本机保存方式。

目前不指定格式或写入格式契约；这些问题在实现导入功能前单独讨论。

三个方向尚未安排具体版本或时间。开发前确认对应的待定问题，完成后再更新 README 的功能状态、当前设计与实际验证记录。
